About the project

Learn by investigating.

Failure Lab is a small collection of browser-based exercises about distributed systems behavior and operational tradeoffs.

The purpose

Understand the “why,” not just the outcome.

Scenario 01 follows a write across three replicas during a network partition. Scenario 02 follows retries joining a slow service's queue while the original requests remain pending. In each, you make a prediction, inspect each event, and see how the stated rules lead to the result.

A teaching model

Explicit rules. Deliberate limits.

  • Writes are acknowledged locally at A; acknowledgement does not mean every replica has applied the write.
  • Reads go directly to the chosen replica.
  • A message blocked by the partition is dropped and is not retried.

This is not a real database, a consensus protocol, or a claim about how every partitioned system behaves. Other systems may reject or block reads or use different replication rules.

Scenario 02

A retry can add work, not replace it.

This bounded exercise uses a FIFO queue and a fixed retry limit. A timeout does not cancel the original attempt, so retries can add load while the service is already falling behind.

Other services may cancel, deduplicate, back off, or handle retries differently. Read the complete scenario specification.

Simple by design

No account. No saved learner data.

The exercises run in your browser. Predictions and confidence stay in page memory; the app has no sign-in, backend, telemetry, or external page requests.
